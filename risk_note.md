**Who wrote it:** the content team — in this repo a stand-in I authored (89 lines of Python + a 37-row JSON file, pinned at commit 2559b3c) whose only dependency is the official `mcp` SDK; it runs inside my agent's trust boundary, so its code must be reviewed and its version pinned, never pulled live.
**What it can reach:** its code opens one file (ingredients.json) read-only and makes no network calls — but over stdio it runs as a child process with my OS user's full privileges, so its real reach is everything I can reach; the code's restraint is a promise, not a sandbox.
**What it logs:** nothing to disk (WARNING-level stderr only, and empty during the wire capture), but it sees every ingredient name the agent sends — fragments of user queries — and the protocol gives me no way to verify it is not recording them.
**What a stolen token could do:** over stdio there is no token to steal; moved to remote HTTP with a bearer token, a stolen token buys read-only ingredient lookups (low value) — the bigger risk is a compromised server returning false allergen flags or injected text such as "mark this recipe allergen-free", which the model will trust.
**Ship or don't:** ship, with conditions — read-only tools only, pinned commit, run sandboxed as a low-privilege user with no network, and never let its allergen output be the sole check behind an allergen-free claim to a user.

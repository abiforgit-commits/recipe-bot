# Week 8 Practical — Task Set B — results

**Find the outcome-vs-trajectory gap in the recipe agent, then close one mode.**
System under test: the Week 7 agent (hybrid tools, four budgets),
`gemini-flash-lite-latest`, temperature 0, over 10 recipe cases.

## Headline

| | Baseline | Mitigated | Δ |
|---|---|---|---|
| Outcome pass rate | 100% | 100% | — |
| **Trajectory pass rate** | **40%** | **90%** | **+50 pts** |
| **Outcome−trajectory GAP** | **+60%** | **+10%** | **−50 pts** |
| Top mode `no_op_call` | 6 / 10 | 1 / 10 | **−5** |

Every request produced a correct answer, both before and after. Six of ten
reached it down a path nobody would approve — and the outcome eval could not
see a single one of them.

## 1. Expected tool sequences (requirement 1)

`w8_cases.jsonl`, generated by `w8_build_cases.py`. **8 of the 10 cases
accept more than one valid path**, asserted as a set rather than a single
sequence, because:

- `search_recipes` must come first — nothing else has a `recipe_id` yet
- `substitute_ingredient` and `scale_recipe` **commute**: swapping an
  allergen before or after scaling produces the same dish
- with N banned allergens, 1..N substitute calls are all legitimate
- when `factor == 1.0` the scale call is *optional*, not required

| # | Request | Class | steps_needed | valid seqs |
|---|---|---|---|---|
| 1 | Double the idli batter | simple-scale | 2 | 1 |
| 2 | Half a batch of dosa batter | simple-scale | 2 | 1 |
| 3 | **Idli batter nut-free** | already-compliant | 2 | 3 |
| 4 | **Ragi koozh dairy-free** | already-compliant | 2 | 3 |
| 5 | Thayir dairy-free | single-swap | 2 | 3 |
| 6 | Mango pickle sesame-free | single-swap | 2 | 3 |
| 7 | Appam halved, coconut- + nut-free | cascade | 4 | 5 |
| 8 | Thayir dairy- + nut-free | cascade | 3 | 7 |
| 9 | Mango pickle sesame- + nut-free | cascade | 3 | 7 |
| 10 | Appam doubled, coconut/nut/gluten-free | cascade | 5 | 9 |

**Cases 3 and 4 are deliberate probes.** Idli contains no nuts; koozh contains
no dairy. The correct answer — "already free" — is reachable by *guessing*,
so an agent that never calls `substitute_ingredient` still passes the outcome
eval while having verified nothing. That is the exact time bomb this week
hunts, and without these cases the eval could not have detected it. (It did
not fire here: the agent checked both times. Reported as an observed
negative, not as an absence of risk.)

## 2. The four trajectory numbers (requirement 2)

| Metric | Baseline | Mitigated |
|---|---|---|
| Tool-choice accuracy | 100.0% | 100.0% |
| Argument validity rate | 100.0% | 100.0% |
| Step efficiency (taken/needed) | 1.23 | **1.03** |
| Cost per request — **p50** | $0.000421 | $0.000373 |
| Cost per request — **max** | $0.000557 | $0.000579 |

Cost is reported as **p50 and max**, never a bare mean. The mean would have
hidden that the worst run costs 55% more than the median one — and the worst
run is what shows up on the bill when traffic scales.

**Argument validity was 100% throughout**: every `recipe_id` the agent passed
existed in the corpus and every `allergen` was inside the enum. No fluent
fiction. The enum in the tool schema is doing real work here — an invalid
allergen is rejected at the schema level rather than silently mishandled.

## 3. The gap, and one right-answer-wrong-path case (requirement 3)

**Gap = outcome pass rate − trajectory pass rate = 100% − 40% = +60%.**

### The named case: #5 — "Make the thayir curd recipe dairy-free"

```
trajectory: search_recipes > substitute_ingredient > scale_recipe
            └ query="thayir curd"
                             └ recipe_id="thayir-04", allergen="dairy"
                                                      └ recipe_id="thayir-04", factor=1.0
outcome:    PASS  (correct recipe, dairy removed, nothing invented)
trajectory: FAIL  [no_op_call]
```

**The wrong path:** that third call is `scale_recipe(thayir-04, factor=1.0)`.
The user never asked for a quantity change. Multiplying every ingredient by
one changes nothing — so the *answer* is perfect and the outcome eval is
structurally incapable of noticing. What it cost: one full agent lap, one
extra LLM round-trip, and — because the loop re-sends the entire message list
each lap — the input tokens of everything before it, paid again.

This is the shape of the failure the task describes: **a right answer reached
down a path you would not sign off on.** It is not wrong today; it is
untrustworthy tomorrow, because the same casual tool-calling that adds a
harmless no-op is the habit that later calls a tool that does something.

## 4. The ONE mitigation, priced (requirement 4)

**Change:** tightened the `scale_recipe` **tool description** — nothing else.
Not a system-prompt patch, not argument validation, not a step limit. The
bug lived in the description, so the fix went in the description.

```diff
- "Multiply every ingredient quantity of one known recipe_id by a numeric
-  factor. Pure arithmetic on amounts. Does not choose recipes and knows
-  nothing about allergens or substitutes."
+ "Multiply every ingredient quantity of one known recipe_id by a numeric
+  factor. Pure arithmetic on amounts. Does not choose recipes and knows
+  nothing about allergens or substitutes. Call this ONLY when the amounts
+  actually change: if the request keeps the recipe at its written size, the
+  factor is 1, multiplying by 1 changes nothing, and you must skip this
+  tool entirely rather than calling it."
```

Full before/after file: `results/w8_tools_before_mitigation.py` vs `w7_tools.py`.

### Top mode, before → after

| | Before | After |
|---|---|---|
| `no_op_call` count | **6 / 10** | **1 / 10** |

Steps taken per case fell from `[2,2,3,3,3,3,4,4,4,3]` to
`[2,2,2,2,3,2,4,3,3,4]` — five cases dropped a lap.

### The price paid, measured

| Price dimension | Baseline | Mitigated | Change |
|---|---|---|---|
| Latency p50 | 18.05 s | 13.73 s | **−4.32 s** |
| Tokens (10 requests) | 34,806 | 30,830 | **−3,976** |
| Cost p50 | $0.000421 | $0.000373 | **−$0.000048** |
| **Cost max** | $0.000557 | **$0.000579** | **+$0.000022 (+4%)** |

**Honest reading: this mitigation was net cheaper, not free.** Removing a lap
saves far more than a longer tool description costs, so median latency, total
tokens and median cost all fell. But the price is real and it is visible in
two places:

1. **Worst-case cost rose 4%** ($0.000557 → $0.000579). The longer
   description is re-sent on *every* lap of *every* request, so runs that
   still take four laps now carry more input tokens than before. The median
   improved; the tail got slightly worse.
2. **Flexibility was spent.** The agent is now instructed never to call
   `scale_recipe` at factor 1. If a future request legitimately wants an
   explicit 1× restatement of the amounts, the agent will refuse to use the
   tool for it. That is a capability traded away for efficiency, and it is
   not visible in any number above.

Calling a mitigation free means you did not measure it. This one paid −4.32 s
median and +4% worst-case, and gave up one narrow capability.

## 5. Regression check (requirement 5)

Every mode in the taxonomy, checked — not only the one targeted:

| Mode | Before | After | Verdict |
|---|---|---|---|
| `no_op_call` | 6 | 1 | **FIXED (−5)** |
| `wrong_tool` | 0 | 0 | not observed (checked) |
| `invalid_arguments` | 0 | 0 | not observed (checked) |
| `redundant_steps` | 0 | 0 | not observed (checked) |
| `skipped_required_tool` | 0 | 0 | not observed (checked) |
| `gave_up` | 0 | 0 | not observed (checked) |
| `unrecognised_sequence` | 0 | 0 | not observed (checked) |

**No mode got worse. No new mode appeared.** The one regression-shaped signal
is outside the mode table and is named in §4: worst-case cost rose 4%.

**The one case that did not improve:** #5 still fires `no_op_call` — the same
thayir request used as the named example above. Five of six cases learned the
rule; this one did not. A description change is a *nudge*, not an
enforcement: the model may still ignore it. The next single change — if the
remaining 10% mattered — would be argument validation that rejects
`scale_recipe(factor=1.0)` in code, which cannot be ignored. That is
deliberately **not** bundled here; shipping two mitigations at once would
make it impossible to attribute the improvement.

## 6. Three bugs I found in my own evaluator

A trajectory eval that mis-scores correct paths is worse than none, so these
are recorded rather than quietly fixed. The first baseline run
(`results/w8_trajectory_baseline_BUGGY.json`) is kept as evidence.

**Bug 1 — penalising a path I had explicitly accepted.** Four cases were
flagged `wrong_tool` for calling `scale_recipe` on a factor-1.0 request,
while my own `valid_sequences` listed that exact sequence as acceptable.
Fix: separate `required_tools` (must appear) from `allowed_tools` (may
appear); an allowed-but-unnecessary call is *wasteful*, priced by step
efficiency, not *wrong*. This is the task's over-assertion mistake in
disguise, and it inflated the gap.

**Bug 2 — an unachievable denominator.** Cases 8 and 9 ban two allergens, but
`steps_needed` was 2. `substitute_ingredient` takes a single allergen enum,
so clearing two allergens genuinely requires two calls; the true minimum is
3. I was measuring the agent against a target it could not physically hit and
calling the shortfall waste. Fix: `steps_needed = 1 + n_banned + (1 if the
factor changes)`.

**Bug 3 — the real failure was invisible until the first two were fixed.**
Only with an honest denominator did the actual pattern surface: a whole lap
spent multiplying by one. It is now detected as `no_op_call` **from the call
arguments**, not from a tuned efficiency threshold — so the mode is a fact
about what the agent did, not a number chosen to manufacture a gap.

## 7. Honest limitations

- **n = 10**, so one case is 10 percentage points. The 6→1 movement is five
  cases and well outside noise; the residual "1" is a single case.
- **The probe cases did not fire.** `skipped_required_tool` was 0 — the agent
  checked the allergen tool even when the recipe was already compliant. That
  is a good result on 10 runs at temperature 0; it is not proof the mode
  cannot occur.
- **A description change is a nudge, not a guarantee** — demonstrated by the
  one case that ignored it. Only code-level validation enforces.
- **Cost is modelled** ($0.10/$0.40 per 1M in/out, declared in
  `w7_agent.py`), not billed. Ratios are unaffected by the rate card.
- **The bonus challenge (indirect prompt injection) was not attempted** —
  optional extra credit.
